# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Static website for the Ticino section of the Swiss Alpine Club (CAS Ticino), published via GitHub Pages from `main` / root of `fole89/casticino-site` (`.nojekyll` → files are served as-is). Currently live at `https://fole89.github.io/casticino-site/`; the `CNAME` file (`casticino.ch`) was removed on purpose until the DNS switch, because with it the github.io URL redirects to the old site — don't re-add it unless asked. Since the site is served from a subpath, use relative links only (no `/…` root-absolute paths). The public base URL is `SITO` in `shared.py` (change it to `https://casticino.ch/` at the DNS switch, together with `site_url`/`display_url` in `admin/config.yml`): `pages.py` uses it to add canonical, `og:url`, absolute `og:image` and `hreflang` (it/de/en) to every page (`metadati()`), and to write `sitemap.xml`, `robots.txt` and `404.html` (served by GitHub Pages for any missing path, so it uses `<base href=SITO>`). `site.js` strips `.html`/`index.html` from the address bar with `history.replaceState` (not on localhost). Plain HTML/CSS/JS: no framework, no build step, no package manager, no tests, no linter. All site content, code comments, commit messages and the README are in **Italian** — keep it that way. The only exception is the German and English version of some pages in `de/` and `en/` (see below).

## Commands

```bash
# Local preview (required for foto.html: opening via file:// blocks the fetch of data/foto.json)
python -m http.server 8000          # then http://localhost:8000/

# Regenerate all pages (or only some: pages.py corsi.html index.html)
python scripts/redesign/pages.py

# Regenerate data/foto.json from the Droptour FTP (needs credentials)
FTP_HOST=… FTP_USER=… FTP_PASSWORD=… python scripts/update_foto.py
```

The scripts use only the Python standard library, except `scripts/prepara_news.py`, `scripts/prepara_mercatino.py`, `scripts/import_news.py` and `scripts/copertine.py`, which need Pillow (`pip install pillow`; the GitHub workflow installs it).

## Architecture

### Pages are generated from Python (scripts/redesign/)
Every page is still a top-level static `*.html` file served as-is, but the HTML is **generated**: `python scripts/redesign/pages.py` rewrites every page — the top-level ones in `PAGES`, the hut pages from `HUT_PAGES`, `cerca.html` and one page per news in `data/news/*.json` (pass file names, e.g. `pages.py corsi.html`, to rebuild only those). **Edit the generator, not the HTML** — a hand edit to a page is lost on the next run. Even with file names, all pages are rendered in memory and `data/cerca.json` is always rewritten; `cerca.html` links `cerca.json` with a fingerprint of the index, so regenerate `cerca.html` too whenever content changes.
- `scripts/redesign/shared.py`: `head()`, `nav()` (menu from `MENU`, `aria-current` on the current page, `is-current` on its parent), `footer()` with sponsor logos, `page_hero()`, `crumbs()`, `subnav()` (sibling pages of La Sezione / Attività), `pic()`/`img()` for `assets/img/*.webp`.
- `scripts/redesign/pages.py`: one function per page with its content (Italian copy lives here), hut data in `HUTS` (home cards) and `HUT_PAGES` (hut pages, one generic `hut()` template), `PAGES` maps file name → function.
- Translated versions, German (`de/`) and English (`en/`): only La Sezione (Introduzione, Comitato, Organizzazione, Capigita, Sede, Storia, Link), the six huts with their sub-pages, Adesione, a reduced home (`de/index.html`, `en/index.html`) and the trip programme `gite.html`/`gita.html` (only the page texts: trip titles, types and Droptour details stay Italian; `GIORNI_BREVI_L`/`MESI_L`/`GRUPPI_L` in `pages.py` and `TESTI` in `assets/gite.js`, chosen from `<html lang>`, must stay aligned; reached from the red nav button, which goes through `L()`; the language switch keeps `?id=`/`?gruppo=` via `site.js`); news, the other Attività pages, Media and PDFs stay Italian-only and are left out of the translated menus (`MENU_DE`/`MENU_EN` in `shared.py`: La Sezione, huts, membership). Same file names as in Italian, under `de/` and `en/`. The language being generated is `shared.LINGUA["lang"]` (`LINGUE` = it, de, en); `de()`/`en()` test it and `tr(it, de, en)` picks the text of the current language; `t()` (`shared.T`) and `tc()` (`pages.TC`) give the fixed UI strings, `L(href)` turns a link into the translated page when one exists (`PAGINE_LINGUA`), the language switch in the nav (`.nav-langs`, one `.nav-lang` link per other language, via `in_lingua()`) points to the same page in each language — below 480px it is hidden and `site.js` shows the languages at the bottom of the mobile menu. Translated texts are written with paths from the site root and translated pages prefixed with `de/`/`en/` (`pubblica()` fixes relative paths by depth); links in hut `link` lists go through `L()`, so they are written without prefix. Hut texts: `scripts/redesign/capanne_de.py` and `capanne_en.py` (`HUT_DE`/`HUT_EN` override the text fields of `HUT_PAGES`, `HUTS_DE`/`HUTS_EN`, `CONTENUTI_DE`/`CONTENUTI_EN` mirror `CONTENUTI`: same keys, images, galleries and PDFs); home, Introduzione, Sede and Adesione: `TRADOTTE` + `*_tradotta()` in `pages.py`; the other section pages use the Italian functions with `tr()` and `RUOLI_*`/`DICASTERI_*`/`STORIA_*`/`LINKS_*`/`CAPIGITA_T`. Pages are registered for both languages in one loop at the end of `pages.py` (`in_lingua_pagina()`). When an Italian hut or section text changes, update the German and English ones too. PDF links get «(italienisch)» / «(in Italian)» automatically. Swiss German spelling (ss, no ß); British English.
- `scripts/redesign/capanne.py`: extra hut content (`CONTENUTI`, keyed by hut page, all six huts): notice (`avviso`), hut text, kitchen (`cucina`), keepers (`team`, optional `persone` shown as small portraits), rates (`tariffe`, cards of label/price rows) and booking notes, access, activities, sub-pages with optional `itinerari` (image, text, optional `dati`, links), history (`storia`), sponsors (`sostenitori`, logos in `…/sostenitori/`), photo groups — copied once from the old hut subsites (e.g. `campotencia.casticino.ch`) and edited only here from now on. Every key is optional: `hut()` in `pages.py` renders only what's there. Sub-pages are generated in `capanne/<cartella>/` (activities, `storia.html`, `foto.html`); images in `assets/img/capanne/<cartella>/`, galleries in `…/foto/<gruppo>-NN-600.webp` + `-1200.webp` (all files of a group are shown, in name order), PDFs in `docs/capanne/<cartella>/`. The «Prenota» button always goes to hut-reservation.org (`booking` in `HUT_PAGES`, built from `PRENOTA`); only Baita del Luca, which isn't there, uses e-mail. `facebook` in `HUT_PAGES` adds a «Dalla capanna» section with the hut's latest Facebook posts: the official Page Plugin iframe, injected by `site.js` (`.fb-feed`) only after the visitor clicks, so no request goes to Facebook before that (no scraping: Facebook blocks it; an automatic import via Graph API needs the page admins' tokens, planned for later). The hut subdomains will later redirect to these pages.
- All styling is in `assets/site.css` (tokens on `:root`, always light: no dark theme on purpose, Geist/Geist Mono self-hosted in `assets/fonts/`, square corners). No inline colors. The visual system is documented in `DESIGN.md` (product context in `PRODUCT.md`).
- Logo: the crest `assets/logo-cas-stemma.webp` (88×104, made from `assets/logo-cas.webp`, which remains the favicon) next to HTML text in the site font, `.brand-text`: «CAS Ticino» bold on top, «Club Alpino Svizzero» smaller below («Schweizer Alpen-Club» on the German pages, `t('logo_sotto')`). Same markup in the nav and in the footer (bigger there).
- Images: `assets/img/<tema>/` — `paesaggi/` (landscape photos, each as `-1000`, `-2000`, `-4x3` mobile crop, `-4x5` vertical crop), `capanne/`, `attivita/`, `corsi/`, `news/` (from the import), `pubblicazioni/` (covers). Names are lowercase, hyphenated, no prefix (the folder says what it is), suffix = size or ratio. In `pages.py` they are referenced without `assets/img/` and `.webp` (e.g. `pic("paesaggi/seraccata", …)`, `img("capanne/adula-3x2", …)`). High-res originals go in `assets/img/originali/` (git-ignored, never published); convert them to WebP in those sizes before use.
- `assets/sponsor/*.webp` are generated from `assets/sponsor/originali/`: trimmed, roughly equal area (max 48px tall), exported at 2x; the footer `<img>` width/height must match.
- Portraits: `assets/img/persone/<gruppo>/<nome-cognome>.webp` (240×280; groups `comitato`, `infrastruttura`, `sport-di-montagna`, `giovani`, `senior`, `comunicazione`, `capigita`). shown as squircles, 96px in Comitato (`COMITATO` in `pages.py`) and 60px in Organizzazione: the file is found from the member's name (`slug_nome()`), so a new photo only needs the right name and folder. Without a photo the initials are shown. `capigita.html` (La Sezione; German `de/capigita.html` «Tourenleitende», role names in `RUOLI_CAPIGITA_DE`, texts in `CAPIGITA_T`) lists the trip leaders from `data/capigita.json` with a role filter (`.filtro` + `data-ruoli`, in `site.js`): the JSON is written by `python scripts/capigita.py <export>.xlsx` from the Droptour export of active leaders, keeping only name, «Capogita dal» and categories (mapped in `CATEGORIE`) — the export holds personal data, so `*.xlsx`/`*.xls` are git-ignored and must never be committed. Optional self-written presentations (one or two sentences, Italian also on `de/`/`en/`) go in `data/capigita-info.json` (key = name as in `capigita.json`): they open in a box on hover/focus/tap of the portrait (`.member--bio`, `.bio`, toggle in `site.js`). Their portraits go in `persone/capigita/`; `foto_persona()` falls back to the same person's photo in another group (e.g. a committee member).
- Long `h1.fit` titles are shrunk at runtime by `site.js` when a word doesn't fit. Verify there's no horizontal scroll at 320–430px after layout changes.

### JavaScript
- `assets/site.js` (loaded `defer` on every page): toggles `.scrolled` on the sticky nav (IntersectionObserver), reveals `[data-reveal]` blocks on scroll, fits `.fit` titles, and builds the mobile menu at runtime by cloning the desktop nav (`.site-nav nav .hide-sm`, `.dd` / `.dd-trigger` / `.dd-menu`, `a.btn` CTA). It relies on that markup and on the `.menu-toggle` button, whose `data-chiudi`/`data-titolo` give the labels of the mobile panel in the page's language — keep those selectors intact when editing the nav.
- Holidays (end of `site.js`): in the week before Carnevale (ends on martedì grasso = Easter − 47), Easter (to Easter Monday), 1 August (25.7–1.8), Halloween (24–31.10) and Christmas (18–26.12) it adds `.festa--<nome>` to `<html>`, an animated icon after the home title (`.festa-icona`) — 3D images `assets/img/feste/<nome>.webp` (Microsoft Fluent Emoji, MIT; the 1 August Swiss flag from Google Noto Emoji, Apache 2.0; notices in `LEGGIMI.txt` there), path resolved from the `site.js` script src so it works at any depth and a light effect over the hero photo (`.festa-strato`: snow, confetti, petals, bats, fireworks); styles and `--festa-*` colours in `site.css`. Decorative only (`aria-hidden`), nothing animated with `prefers-reduced-motion`. Preview any day with `?festa=natale|halloween|pasqua|carnevale|agosto` (`?festa=no` turns it off).
- `assets/gite.js` (`gite.html`, `gita.html` and their `de/`/`en/` versions): reads the trip programme live from the public Droptour API, falling back to `data/gite.json`. `scripts/update_gite.py` (daily, `.github/workflows/update-gite.yml`) writes that copy, including each trip's detail sheet (`scheda`, rows reduced like `righeScheda()` in `gite.js`, «Capogita» rows skipped): `gita.html` shows it at once and replaces it when Droptour answers (sometimes slowly), giving up after 8 s.
- `assets/foto.js` (only `foto.html`): fetches `data/foto.json` and renders albums into `#albums` with a gallery per album, paginated 5 at a time via `#load-more`.

### Trip programme (gite.html)
`gite.html` mirrors the Droptour programme in the site style; registration, login and trip details stay on Droptour (each trip links to its `page=detail&touren_nummer=` page). Data come from Droptour's public XML interface (`GITE_API` in `pages.py`: `/casticino/dropnetapps/tours/api/?action=command&command=getItems`, CORS open): `assets/gite.js` reads it live in the browser and re-renders the list with the same markup as `gita_html()` in `pages.py` (keep the two in sync), builds the group/type filters (`?gruppo=Giovani&tipo=COR` preselects them; trips of group «Tutti» match every group) and falls back to `data/gite.json` if Droptour doesn't answer. `scripts/update_gite.py` writes that snapshot (stdlib only; only trip data and the leaders' names — the interface and the RSS also carry e-mails, never store them); `.github/workflows/update-gite.yml` runs it daily (04:47 UTC) and regenerates `gite.html`, `index.html` and `cerca.html` (static list for no-JS, the home «Prossime gite» — next 3 from the snapshot, `prossime_gite()`, without cancelled trips and without the «Colonna di soccorso» evenings — and one search entry per trip). Each trip opens `gita.html?id=<Droptour number>` (one template, `gita_pagina()`, filled by the same `gite.js`: header and status from the list, texts from the Droptour card `command=getItem&item_id=` reduced to plain text; red «Iscriviti su Droptour» button to the Droptour detail page; not in the sitemap; search entries link there). `GITE` in `shared.py` is `gite.html`; `GITE_DROPTOUR` is the Droptour portal; Giovani/Senior/Corsi link to `gite.html` with the filter preset.

### Photo pipeline
`scripts/update_foto.py` → `data/foto.json` → `assets/foto.js`.
- The script lists via FTP(S) the image files directly inside `<FTP_BASE>/<year>/AAAA-MM-GG-titolo---luogo/` (current and previous year; the script default for `FTP_BASE` is `/casticino/dropbox/photo/gite`, but for this FTP account the path is `/photo/gite`, set via the repo variable). Over FTP there are no `thumbnails/`/`mysize/` subfolders — those exist only on the web server, with the same file names — so it writes public URLs `<PUBLIC_BASE>/…/thumbnails/<file>` and `…/mysize/<file>` on ssl.dropnet.ch. Keeps the newest `MAX_ALBUMS` (default 15) non-empty folders; future trips have empty folders and are skipped. If nothing is found it exits with an error instead of emptying `foto.json`. The Droptour FTP server answers 450 (not 550) for missing paths. **Images are never copied into the repo.**
- Title, place, report text (`text`) and `link` come from `fetch_droptour()`, which scrapes the public Droptour gallery page (`GALLERY_URL`, no login; the admin `member_bericht` page needs login and is not used). Each `<div id="dropapp-tours-galery-<nr>">` block is matched to a folder via its `/…/<folder>/mysize/` URL; title is the last `<h2>` split on the last ` - ` into title/place; text is `droptours-description-<nr>` converted to plain text with `\n` between paragraphs (rendered with `white-space:pre-line`); link is the public `page=detail&touren_nummer=<nr>` page. If the page is unreachable it falls back to the folder slug (`---` separates title from place; canton codes uppercased). `data/foto-overrides.json` (key = folder name, fields `title`, `place`, `text`, `link`; keys starting with `_` ignored) always wins over both — keep it for real exceptions only.
- The file is only rewritten when `albums` changes.
- `.github/workflows/update-foto.yml` runs it daily (04:17 UTC) and on manual dispatch, then (if it changed) regenerates `data/cerca.json`, `index.html` and `cerca.html` and commits them with `data/foto.json` as `casticino-bot` if it changed. Config comes from secrets `FTP_HOST`/`FTP_USER`/`FTP_PASSWORD` and optional vars `FTP_BASE`, `FTP_TLS`, `PUBLIC_BASE`, `MAX_ALBUMS`.

Don't hand-edit `data/foto.json` for lasting changes — edit `data/foto-overrides.json` instead.

## Content conventions
- Page file names are all lowercase (`campotencia.html`, `corsi.html`, `de/comitato.html`…): GitHub Pages also serves them without `.html`, so `casticino.ch/campotencia` works as a short alias. URLs are case-sensitive, so never give a page a capital letter. Internal links keep `.html` (the local preview with `http.server` doesn't resolve extensionless paths).
- PDFs live in `docs/<tema>/` (`statuto-visione`, `scale-difficolta`, `promemoria`, `cartine`, `moduli`, `corsi`, `noleggio`, `annuari`, `informazione`, `news`) with lowercase hyphenated Italian names, no accents or version suffixes, year only when the document is year-specific (e.g. `corsi/sci-alpinismo/programma-2027.pdf`; each course has `obiettivi.pdf`, `materiale.pdf` and `programma-<anno>.pdf` in `docs/corsi/<corso>/`, linked by `schede_corso()` in `pages.py`); they are linked from `pages.py` as `DOC + "<tema>/<file>.pdf"`. Replacing a document keeps its name so links stay valid; never link to `casticino.ch/wp-content/…`, which disappears at the domain switch.
- Menu: La Sezione, News (goes straight to `news.html`, the list of all news), Attività (Giovani, Senior, Corsi, Soccorso — a placeholder page until the rescue info arrives —, Noleggio, Mercatino; the trip programme is only the red «Programma gite» button, which goes to `gite.html`), Capanne, Media (Foto e resoconti — the page is still `foto.html` —, Annuari, Informazione, Documenti; the «Media» item itself goes to `foto.html`, the home has no Media section), Adesione — all from `MENU` in `shared.py` (nav, footer columns and the `subnav()` rows follow it).
- News: one JSON file per news in `data/news/<AAAA-MM-GG>-<titolo>.json` (fields documented in `scripts/redesign/news_util.py`: `title`, `date` as `AAAA-MM-GGTHH:MM` — the time only orders news of the same day —, `image`, `alt`, `excerpt` (optional, else the start of the text), `testo` in Markdown for new news or `html` for those imported from the old WordPress with `scripts/import_news.py`, `allegati` (PDF list), `file`). `news_util.py` reads them, converts the Markdown (own small converter, stdlib only; HTML in the text is shown as text, only http/https/mailto/tel or relative links) and computes the page name `news/<anno>/<AAAA-MM-GG>-<titolo-breve>.html` (`nome_breve()`: no leading weekdays/dates, no articles/prepositions, ≤40 chars). `pages.py` builds `news.html` (latest + archive by year), one page per news (relative paths fixed with `in_sottocartella()`) and the 3 latest on the home. Images in `assets/img/news/<anno>/` and PDFs (attachments or links in the text) in `docs/news/<anno>/`, both named like the page (`-2`, `-3`… for further files).
- News (and Mercatino) editing area: `admin/` (Decap CMS from unpkg, `admin/config.yml`, preview template with `site.css` in `admin/index.html`; `<base href="../">` so paths are from the site root). Editors log in with GitHub (collaborators with Write access) through the Cloudflare Worker in `scripts/cms-auth/worker.js`; setup and editor guide in `scripts/cms-auth/LEGGIMI.md`. Saving commits the JSON (and uploaded photos into `assets/img/news/`, PDFs into `docs/news/`); `.github/workflows/news.yml` then runs `scripts/prepara_news.py` (sets `file`, converts uploaded photos to WebP ≤1400px into `assets/img/news/<anno>/`, moves uploaded PDFs from `docs/news/` into `docs/news/<anno>/`, and rewrites their paths, removes pages of deleted news and the photos/PDFs in the year folders that no news references any more) and `pages.py`, and commits as `casticino-bot`. To add a news by hand, create the JSON (only `title`, `date`, `testo` are needed) and run `prepara_news.py` + `pages.py`.
- Mercatino (`mercatino.html`, under Attività): listings of mountain gear between private people, one JSON per listing in `data/mercatino/<AAAA-MM-GG>-<titolo>.json` (fields documented in `scripts/redesign/mercatino_util.py`: `tipo` Vendo/Cerco/Regalo, `title`, `date`, optional `scadenza` — default 90 days after `date` —, `concluso`, `prezzo`, `luogo`, `testo` plain text, up to 3 `foto`, `nome`, `contatto` shown as written, e-mails/phones become links). Members send listings by e-mail (the «Pubblica un annuncio» button is a prefilled `mailto:` to `MERCATINO_MAIL` in `pages.py`) and the editors enter them in the same `admin/` area (collection «Mercatino», preview in `admin/index.html`). `.github/workflows/news.yml` also runs `scripts/prepara_mercatino.py` (uploaded photos → WebP ≤1200px named `assets/img/mercatino/<nome-annuncio>-N.webp`, removes photos no listing uses); `pages.py` shows only listings already published, not expired and not `concluso`, with the `.filtro` type filter; `update-gite.yml` regenerates `mercatino.html` every morning so expired listings disappear, and `site.js` also removes `.annuncio[data-scade]` older than today. Expired/concluded JSON files stay (renewable by moving `scadenza`).
- Annuari / Informazione: drop the PDF in `docs/annuari/annuario-<anno>.pdf` or `docs/informazione/informazione-<anno>-<mese>.pdf`, run `python scripts/copertine.py` (needs PyMuPDF + Pillow, only for that script) to render the cover into `assets/img/pubblicazioni/`, then regenerate: the pages list every file, newest first.
- Search: `pages.py` writes `data/cerca.json` (title, url, type and plain text of every generated page except `news.html`/`cerca.html` and the translated pages in `de/` and `en/`, plus PDFs, annuari, Informazione, Link utili and the photo albums in `data/foto.json`) on every run; `cerca.html` + `assets/cerca.js` search it in the browser (accent-insensitive, all words must match, title weighs more). The magnifier in the top bar links to it. When `data/foto.json` changes, the daily photo workflow also runs `pages.py index.html cerca.html`, so new albums reach the search index without touching other pages.
- DNS: only the site records move to GitHub; MX/TXT mail records and hut subdomains (e.g. `capannacristallina.casticino.ch`) must not be touched.
